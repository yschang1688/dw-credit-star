# BI 資料集與儀表板規格

從倉儲匯出的整齊資料集（`extract/`），供 Tableau／Power BI 直接連接。`etl/export_bi_extract.py` 產出，可重複執行。

## 為什麼是五張小表而不是一張大寬表

BI 端最常見的錯誤是拿一張混合粒度的寬表做聚合，把「客戶月」和「客戶」混在一起算，平均值因重複計數而失真。所以每張表**粒度單一且寫在檔頭**：

| 檔案 | 粒度 | 列數 | 用途 |
|---|---|---:|---|
| `risk_tier_by_month.csv` | 風險等級 × 月份 | 18 | 趨勢圖：逾期率、使用率隨月份變化 |
| `tier_migration.csv` | 前月等級 × 本月等級 | 9 | 遷移矩陣熱圖（**只有 SCD Type 2 答得出來**，維度就地覆寫的話歷史等級早就不存在） |
| `default_by_tier.csv` | 觀測期末風險等級 | 3 | 風險分層的鑑別力（HIGH 組違約率 69.6% vs LOW 組 13.2%） |
| `version_counts.csv` | 版本數 | 6 | SCD2 版本分布：16,598 位從未變更、最多變更 5 次 |
| `quality_results.csv` | 品質規則 × 批次 | 12 | **讓儀表板顯示資料品質，而不只有業務數字** |

**比率一律存分子分母、不存比率**（與倉儲層同一條規則）。BI 端要算逾期率或使用率時，先各自加總再相除；直接對每列比率取平均會得到「平均的平均」，小額與大額帳戶被當成等權，結論會偏。

## 工作簿規格（照此建置）

### 計算欄位

在 Tableau 建以下計算欄位，**全部寫成「先加總再相除」**：

```
逾期率      = SUM([Delinquent Months]) / SUM([Customer Months])
額度使用率  = SUM([Bill Amount Sum]) / SUM([Credit Limit Sum])
違約率      = SUM([Defaults]) / SUM([Customers])
遷移比例    = SUM([Customer Months]) / TOTAL(SUM([Customer Months]))   // 表計算，依「前月等級」分區
月份        = DATE(DATEPARSE("yyyyMM", STR([Month Key])))
```

> 遷移比例務必用 `TOTAL(...)` 並把分區設為「前月等級」——遷移矩陣要看的是「LOW 的人下個月跑去哪」，分母是該列的總和，不是全表總和。分區設錯會讓每格都變成佔全體比例，矩陣就失去意義。

### 四張工作表

1. **遷移矩陣（熱圖）**：列＝前月等級、欄＝本月等級、顏色＝遷移比例、標籤＝百分比。色階用**發散型**並以「維持原等級」為中性點，讓升降級一眼可辨。
2. **風險分層鑑別力（橫條）**：軸＝違約率、列＝風險等級（HIGH／MEDIUM／LOW 依序），標籤同時顯示客戶數——只給比率不給母數，讀者無法判斷可信度。
3. **逾期率趨勢（折線）**：X＝月份、Y＝逾期率、顏色＝風險等級。註記整體從 10.3% 惡化到 22.7%。
4. **資料品質看板（表格）**：規則代碼、嚴重度、判定、失敗列數；ERROR／WARN 以顏色區分。**WARN 要顯示不要藏**——3 條 WARN 是來源本來就髒（未定義碼值），標記出來才有人去追。

### 儀表板佈局

單頁，上方兩張（遷移矩陣、分層鑑別力）、下方兩張（趨勢、品質看板）。加一段文字說明資料來源與粒度。**品質看板放在同一頁而不是另開一頁**——業務數字與它的可信度應該被一起看到。

## 發佈到 Tableau Public（網頁版即可，免裝 Desktop）

Tableau Public 的 **web authoring** 可直接在瀏覽器建 viz，但一次只能上傳一個檔案——故 `extract/dw_credit_star_bi.xlsx` 把五張表合成單一 Excel（含 README 工作表：粒度與計算欄位公式）。

1. 登入 public.tableau.com → 右上 **Create** → **Web Authoring**（或個人頁的 Create a Viz）
2. 上傳 `bi/extract/dw_credit_star_bi.xlsx`；五張資料表各自成為可拖入的工作表
3. 依上述規格建計算欄位與四張工作表 → 組成單頁儀表板
4. **Publish**（網頁版的儲存即發佈——Tableau Public 上的一切都是公開的）
5. 把公開連結貼回本 README 與履歷

發佈需帳號登入，**由本人操作**；資料為 UCI 公開資料集，無個資疑慮。
